Deploy it on your lab

Runs on Databricks Free Edition. Demo lab first, then your logs.

Deploy the demo Log format Labels Switch to your data Every morning

1Deploy the demo

The first run builds a 15-bench demo lab so you can watch the whole job work, report included.

git clone https://github.com/rpuranikx/NightShift
cd NightShift
databricks auth login --host https://<your-workspace>.cloud.databricks.com
databricks bundle deploy
databricks bundle run nightshift_nightly

Tables land in workspace.nightshift. Raw files go in /Volumes/workspace/nightshift/raw_logs.

2Export your logs in this shape

Your bench PCs probably log differently. Write a small exporter that drops these files in the volume. Timestamps can be ISO or epoch seconds.

runs/<date>_<bench>.jsonl one line per event, new files every night

{"event": "test_result", "result_id": "…", "run_id": "…",
 "bench_id": "DUO-03", "build_id": "B1005", "suite": "smoke",
 "test_name": "boot_to_home", "display": 2,
 "started_at": "2026-10-27T23:14:02", "duration_s": 88.4,
 "status": "FAIL", "error_message": "error: device offline",
 "screenshot_path": "…"}
{"event": "watchdog_reboot", "run_id": "…", "bench_id": "DUO-03",
 "at": "1761607200", "reason": "no heartbeat for 15 min"}

status is PASS, FAIL or ERROR. error_message can be null. result_id is unique per result; retried duplicates are fine.

benches.csv one row per bench

bench_id,display_count,pcm_link,pc_hostname,lab,commissioned_on
DUO-03,2,molex,HIL-PC-11,Lab B,2025-03-02

builds.json the builds under test

[{"build_id": "B1005", "version": "v2.4.2",
  "built_at": "2026-10-14T17:31:00", "release_night": 16}]

3Label a few weeks of failures

The model learns from your lab’s history. Most labs already have it in old triage notes or defect tickets. A couple of thousand labeled failures is plenty.

ground_truth.csv
result_id,true_category
…-smoke-boot_to_home-d2,hardware_adb

Categories are script, framework, hardware_adb and real_defect.

4Switch off the demo pieces

In resources/nightshift.job.yml, remove the generate_logs task and make bronze_ingest depend on setup. Then replace the checks in src/checks/check_gold_tables.py with things you know are true about your lab, like every bench reported last night.

- task_key: bronze_ingest
  depends_on:
    - task_key: setup

To run when the logs arrive instead of on a schedule, add a file arrival trigger and redeploy.

nightshift_nightly:
  trigger:
    file_arrival:
      url: /Volumes/workspace/nightshift/raw_logs/runs/

5Every morning

Read the report. Then open 05_triage_feedback and record the real cause for the handful of unsure calls. That’s the only manual triage left, and it makes tomorrow’s model better.
